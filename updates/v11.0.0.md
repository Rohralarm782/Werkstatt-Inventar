# v11.0.0 — 05.10.2026

Grundlage: Repo-Stand `dfdef13` (10.1.0, Commit vom 05.10.2026).

Änderung an der Datenstruktur (Tabelle umbenannt, neue Tabellen, Spalten
entfernt, Daten umgebaut), daher 11.0.0.

## Was wurde geändert und warum

Mit Unterkategorien konnte ein Teil nur an einer Stelle stehen. Teile, die
nicht eindeutig zuzuordnen sind (Kettenblattschrauben: „Kurbel“ oder
„Kleinteile“?), waren dadurch schwer zu finden.

### Tags statt Unterkategorien
- Tags gehören **weiterhin zu einer Kategorie** (Buchstabe im Code), z. B.
  „Schläuche“ nur bei Laufrad & Reifen. Im Formular erscheinen nur die Tags
  der eigenen Kategorie.
- Neu: ein Artikel oder Einzelstück kann **mehrere Tags** seiner Kategorie
  haben.
- Codes, Nummern und Etiketten ändern sich nicht.

### Bedienung wie bisher
- Lager und Inventar: Kategorie antippen → an derselben Stelle ihre Tags
  („Kurbel · 1“, „Kleinteile · 2“, „ohne Tag · 1“), Tag antippen → nur
  dieser, × = zurück. Ein Artikel mit zwei Tags zählt bei beiden.
- Gliederung der Listen: Überschrift ist der **erste** Tag eines Eintrags
  (nach der Reihenfolge unter Mehr → Tags). Jeder Eintrag steht dadurch nur
  einmal in der Liste; ist ein Tag-Filter gesetzt, gibt es keine
  Zwischenüberschriften.
- **Suche** findet auch Tag-Namen (Lager, Inventur, Inventar).
- Lager-Liste: Tags stehen als kleine Chips unter dem Artikelnamen.

### Formulare
- Neuer Artikel, Artikel bearbeiten, Neues Einzelstück, Einzelstück
  bearbeiten, Serie bearbeiten: Feld **Tags** mit Chips zum An-/Austippen.
- „+ neuer Tag“ im Formular legt direkt einen Tag in der Kategorie an und
  wählt ihn aus.
- Beim Anlegen mit automatischer Nummer werden die Tags in derselben
  Datenbankfunktion gespeichert. Beim Bearbeiten bzw. mit eigener Nummer
  folgt `tags_setzen` direkt nach dem Speichern.

### Mehr → Tags (vorher „Unterkategorien“)
- Gleicher Aufbau: Kategorien → Tags, hinzufügen, umbenennen/löschen, ↑.
- **Zuordnen** neu: Tag wählen, angehakt ist, wer ihn schon hat; an- und
  abhaken, Speichern gibt bzw. nimmt den Tag (andere Tags bleiben).
  „nur ohne Tag / alle / keine“ wie bisher. Serien sind eine Zeile.

### Export
- Spalte „unterkategorie“ heißt jetzt „tags“ (mehrere mit Komma getrennt).

### Sicherheitsnetz
- Ist die Migration noch nicht ausgeführt, läuft die App ohne Tags weiter
  (Mehr → Tags weist darauf hin). Umgekehrt läuft die alte 10.1.0 nach der
  Migration weiter, nur ohne Unterkategorien. Die Reihenfolge
  Migration/Hochladen ist daher egal.

### Technisch
- Datenbank:
  - `unterkategorie` → `tag` umbenannt (ids, Rechte, Zugriffsregeln bleiben;
    Constraints und Sequenz mit umbenannt).
  - Neu: `artikel_tag (code, tag_id)`, `stueck_tag (nummer, tag_id)`;
    löschen eines Tags / Einzelstücks entfernt die Zuordnung mit.
  - Alle bisherigen `unterkategorie_id` werden übernommen, danach die
    Spalten `artikel.unterkategorie_id` und `stueck.unterkategorie_id`
    entfernt.
  - `artikel_anlegen` / `stueck_anlegen` (gleiche Signatur) lesen
    `p_daten -> 'tags'`.
  - Neue Funktionen `tags_setzen(art, schlüssel[], tags[])` und
    `tag_zuordnen(tag, art, mit[], ohne[])` — übernehmen nur Tags der
    passenden Kategorie.
  - Zuordnungstabellen von außen nur lesbar, geändert wird über die
    Funktionen.
- App: neue Helfer `tagDa`, `tagListe`, `tagNachId`, `tagsVon`, `tagChips`,
  `tagNamen`, `tagAuswahl`, `tagsImFormular`, `uzListe`, Aktionen
  `tagUmschalten`, `tagNeuImFormular`, Änderung `uzTag`. Die Namen
  `ukBox`, `ukVerw`, `ukFilter` usw. sind geblieben (intern), zeigen aber
  Tags. `serienSchluessel` enthält die Tags.

## Manuelle Schritte

Vorher muss `db/migration_10.0.0.sql` gelaufen sein (ist laut Hauke online).

1. Empfohlen: in Neon einen Branch anlegen und die Migration dort zuerst
   ausführen.
2. Neon → SQL-Editor: `db/migration_11.0.0.sql` komplett ausführen.
3. Neon → Data API → **„Refresh schema cache“**.
4. Dateien ins Repo hochladen.
5. App neu laden, unten muss „Version 11.0.0“ stehen.
6. Mehr → Tags: die bisherigen Unterkategorien stehen dort als Tags;
   zusätzliche Tags vergeben (Formular oder „Zuordnen“).

## Geprüft

- JavaScript-Syntax (node --check).
- Postgres 16: Stand 10.0.0 (`schema.sql` vor diesem Update) mit
  Testdaten + `migration_11.0.0.sql` ergibt dasselbe Schema wie die neue
  `schema.sql` auf leerer Datenbank (pg_dump verglichen, inkl. Rechte und
  Zugriffsregeln). Unterkategorie-Zuordnungen kamen als Tags an.
- Als anonymer Nutzer: `tags_setzen` (Tag einer fremden Kategorie wird
  ignoriert), `tag_zuordnen` (geben/nehmen, fremde Kategorie ignoriert),
  `artikel_anlegen` mit Tags, Tag löschen entfernt Zuordnungen.
- Oberfläche im Browser (Chromium, 400 px) mit nachgebauten
  Datenbank-Antworten: Kategorie → Tags mit Zählung (Mehrfach-Tag zählt
  doppelt), Tag-Filter, Suche nach Tag-Namen, Formular (Tags nur der
  Kategorie, wechseln mit der Kategorie-Auswahl), Speichern ruft
  `tags_setzen` bzw. `artikel_anlegen` mit `tags`, Mehr → Tags, Zuordnen
  (Haken je Tag, `tag_zuordnen`), Inventar — keine Fehler.
- Nicht gegen die echte Neon-Datenbank getestet.

## Bekannte offene Punkte

- Die Bestellliste und die Inventur-Ansicht sind weiterhin nicht nach Tags
  gegliedert (Suche nach Tag-Namen geht).
- Speichern beim Bearbeiten sind zwei Anfragen (Stammdaten, dann Tags).
  Bricht dazwischen die Verbindung ab, sind die Stammdaten gespeichert, die
  Tags nicht — dann einfach nochmal speichern.
