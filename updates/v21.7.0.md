# 21.7.0 — 18.11.2026

**Grundlage:** Commit `c035bed` (21.6.2)

## Was wurde geändert und warum

### Artikel löschen
In der Artikel-Übersicht (Mehr → Artikel) gab es keinen Löschknopf. Seit 4.0.0
konnten Artikel nur auf „inaktiv“ gesetzt werden, die Datenbank erlaubte kein
Löschen. Für Fehleingaben (falsch angelegt, doppelt) ist das unpraktisch.

- Neue Datenbankfunktion `artikel_loeschen(code)` (Migration 21.7.0), nur
  Werkstatt-Manager und Gesamt-Admin, nur am eigenen Standort.
- Abgelehnt mit Meldung, wenn der Artikel
  - in einem Ticket-Schritt steht (egal welcher Status),
  - an Sportler/Kostenträger ausgegeben, verliehen oder abgerechnet wurde
    (Buchung mit Sportler, Ticket, Rechnung oder „abrechnen“),
  - von einer Pauschale verbraucht wird („Verbraucht dabei“).
  Dann bleibt „inaktiv“ der Weg.
- Sonst gehen mit: reine Lagerbuchungen (Zugang, Umbuchung, Inventur-Korrektur,
  Storno, Werkstatt-Entnahme), Zählungen, Bestellungen, Packlisten-Zeilen und
  Tags. Alles in einer Funktion, ganz oder gar nicht.
- App: Knopf „löschen“ in der Artikel-Übersicht und „Löschen“ in „Artikel
  bearbeiten“, nur für Manager sichtbar (`MANAGER_NUR`). Vorher Rückfrage; liegt
  noch Bestand im Lager, nennt sie die Menge.

### „Was ist neu?“
Eintrag 21.7.0 für Manager.

## Manuelle Schritte
1. Neon SQL-Editor → `db/migration_21.7.0.sql` komplett ausführen
   (vorher muss 21.6.1 gelaufen sein).
2. Data API → „Refresh schema cache“ (neue Funktion, sonst „function not found“).
3. Dateien hochladen.

## Geprüft
- JavaScript-Syntax aller geänderten Dateien (`node --check`).
- Lokal in Postgres: Schema 21.6.1 + Migration 21.7.0 ergibt dieselben
  Funktionen und Rechte wie die neue `schema.sql`.
- Funktion mit Testdaten: Artikel mit Zugang, Umbuchung, Storno, Bestellung,
  Packliste und Tag wird gelöscht; Artikel mit Ausgabe an Sportler, mit
  Ticket-Schritt oder als Verbrauch einer Pauschale wird abgelehnt; Trainer
  bekommt „Keine Berechtigung“.
- Nicht gegen die echte Neon-Datenbank getestet.
