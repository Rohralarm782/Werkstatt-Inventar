# Update v20.5.0

**Datum:** 08.10.2026
**Grundlage:** Commit `8718a88`, Version 20.4.0

Sammel-Update: Am 08.10. wurden in mehreren Chats Updates gebaut, die nicht
ins Repo gekommen sind (teils auf älterem Stand und mit doppelt vergebenen
Versionsnummern: „20.2.1“ Icon, „20.3.0“ Ticket zuweisen, „20.3.1“ Scanner,
„20.5.0“ Benachrichtigungen). Sie sind hier zusammen auf den aktuellen Stand
gesetzt. Die einzeln ausgelieferten ZIPs dieser Chats bitte **nicht** mehr
hochladen. Nichts davon ist bisher in Neon ausgeführt.

## Was wurde geändert und warum

### 1. Ticket beim Anlegen gleich zuweisen

Bisher war ein neues Ticket immer „offen“; wer es selbst bearbeiten wollte,
musste es danach extra übernehmen. Jetzt gibt es im Formular „Neues Ticket“
ganz unten **„Wer macht es?“**:

- *Noch offen — übernimmt später jemand* (Vorgabe, wie bisher)
- *Ich (Name)*
- jede andere aktive Person mit Rolle Werkstatt-Manager oder Trainer am
  Standort

Ist jemand gewählt, erscheint der **Arbeitsaufwand** (klein / mittel / groß),
vorgewählt nach den Arbeitsschritten, sonst „klein“. Das Ticket ist dann
sofort „in Arbeit“ bei dieser Person (steht bei ihr unter „Meine“ und in
ihrer Benachrichtigung). Ob die Person zulässig ist, prüft die Datenbank.
Sportler legen Tickets wie bisher an, ohne Zuweisung. Ohne Migration fehlt
das Feld einfach.

### 2. Benachrichtigungen 07:00–18:00, halbstündlich, Start über cron-job.org

- Uhrzeit wählbar von 07:00 bis 18:00 zur vollen oder halben Stunde (bisher
  07:00–12:00 im Viertelstunden-Takt). Gespeicherte Zeiten auf :15/:45 setzt
  die Migration auf die nächste halbe Stunde (07:15 → 07:30, 08:45 → 09:00).
- Der Zeitplan von GitHub hat den Workflow am 08.10. kein einziges Mal
  gestartet. Deshalb gibt es im Workflow **keinen GitHub-Zeitplan mehr**;
  angestoßen wird er von cron-job.org (alle 30 Minuten, 7:00–18:30 Uhr) oder
  von Hand. Jeder zusätzliche Lauf würde die Datenbank wecken.
- Außerhalb 07:00–19:00 beendet sich der Lauf sofort, ohne die Datenbank
  anzufassen.

### 3. Neues App-Symbol

Leicht eingedrückter Reifen mit fünf Speichen auf Anthrazit, darunter eine
kurze rote Linie (Entwurf „U1 a“). Alle fünf Dateien in `icons/` ersetzt;
Badge für die Statusleiste weiß auf transparent (nur Reifen und Nabe).
Icon-Verweise in `index.html` und `manifest.webmanifest` mit `?v=20.5.0`.

### 4. Scanner: Strichcode erst nach zweimal gleichem Lesen

Beim ersten Scan kam „Unbekannter Code: C#F&4“ — ein Code-128-Fehllesen aus
einem noch unscharfen Bild (Code 128 hat nur eine einfache Prüfsumme).
Ein Strichcode gilt jetzt erst, wenn derselbe Inhalt zweimal innerhalb von
2,5 s gelesen wurde; ein einzelnes Fehllesen wird still verworfen. QR-Codes
und Data Matrix gelten weiter sofort. Pause zwischen zwei Bildern 150 statt
300 ms, damit die zweite Lesung schnell kommt.

## Manuelle Schritte (in dieser Reihenfolge)

1. **Neon → SQL-Editor:** `db/migration_20.5.0.sql` komplett ausführen
   (vorher muss `migration_20.2.0.sql` gelaufen sein). Optional vorher auf
   einem Neon-Branch testen.
2. **Data API → „Refresh schema cache“.**
3. **Dateien hochladen** und gleich veröffentlichen (Actions → „App
   veröffentlichen“ → „Run workflow“). Bis dahin bietet die alte App noch
   :15/:45 an; das Speichern solcher Zeiten lehnt die Datenbank mit einer
   Meldung ab.
4. **GitHub-Token** für cron-job.org: github.com → Profilbild → Settings →
   Developer settings → Personal access tokens → **Fine-grained tokens** →
   „Generate new token“: nur Repository `Werkstatt-Inventar`, Permissions →
   Repository → **Actions: Read and write**, sonst nichts. Ablauf z. B.
   1 Jahr (Datum notieren). Token kopieren.
5. **cron-job.org** → „Create cronjob“:
   - URL: `https://api.github.com/repos/rohralarm782/Werkstatt-Inventar/actions/workflows/push-morgen.yml/dispatches`
   - Zeitplan: Minuten 0 und 30, Stunden 7–18, täglich, Zeitzone
     Europe/Berlin
   - Methode POST, Body `{"ref":"main"}`
   - Header: `Authorization: Bearer <Token>`,
     `Accept: application/vnd.github+json`,
     `Content-Type: application/json`, `X-GitHub-Api-Version: 2022-11-28`
   - „Test run“ muss **204** zeigen; in GitHub erscheint ein neuer Lauf.
6. Auf installierten Handys wechselt das App-Symbol nicht sofort: Android
   übernimmt es nach einiger Zeit, am iPhone die App vom Home-Bildschirm
   entfernen und neu hinzufügen.

## Geprüft

- Lokales Postgres 16: alter Stand (schema.sql aus `8718a88`) + Migration
  ergibt dasselbe Schema wie die neue schema.sql (`pg_dump -s`, inkl. Rechte).
- Rundung gespeicherter Uhrzeiten: 07:15 → 07:30, 08:45 → 09:00, 12:00 und
  11:30 unverändert.
- Als Rolle `anonymous`: `werkstatt_personen()` liefert nur aktive
  Manager/Trainer des Standorts; Zuweisen an Manager (Groß-/Kleinschreibung
  egal) → „angenommen“ mit Name und Aufwand; ohne Zuweisung oder mit leerem
  Namen → „offen“; Geschäftsstelle, deaktiviertes Konto und unbekannter
  Aufwand werden abgelehnt. `push_einstellung_setzen`: 17:30 und 18:00 gehen,
  07:15, 18:30 und 06:30 werden mit Meldung abgelehnt.
- Morgenlauf: um 18:45 versucht er die Datenbank zu erreichen, ab 19:00
  beendet er sich ohne Datenbank.
- Oberfläche (Playwright, Handy-Breite, Datenbank nachgebildet): Auswahl
  „Wer macht es?“ mit Ich und anderen Personen, Aufwand erscheint nach
  Auswahl, Aufruf schickt `p_zuweisen`/`p_aufwand`, Meldung „zugewiesen an …“;
  ohne Migration kein Feld und Aufruf ohne neue Angaben. Uhrzeitauswahl
  07:00–18:00 in 23 Schritten. Keine JavaScript-Fehler.
- Scanner (Chromium, nachgestellte Lesungen): „C#F&4“ + zweimal `C-206` →
  `C-206`; nur einmal „C#F&4“ → nichts; QR einmal → sofort.
- Icons erzeugt und angesehen, `manifest.webmanifest` gültiges JSON.
- Syntax aller JavaScript-Dateien (`node --check`).

**Nicht geprüft:** gegen die echte Neon-Datenbank, der Aufruf von
cron-job.org an die GitHub-API, Scanner und App-Symbol auf einem echten
Handy.
