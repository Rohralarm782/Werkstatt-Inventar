# v20.0.1 — 07.10.2026

Kleine Anpassung am Ablauf, keine Änderung an App-Code oder Datenbank, daher 20.0.1.

## Was wurde geändert und warum

In Greifswald wird jetzt aktiv mit der App gearbeitet. Bisher ging jeder
Upload nach `main` sofort live, also möglicherweise mitten in der Arbeit.
Nicht dringende Updates sollen deshalb nachts live gehen.

- Neuer Workflow `.github/workflows/veroeffentlichen.yml`:
  - **jede Nacht** um 1:17 UTC (3:17 Uhr Sommerzeit, 2:17 Uhr Winterzeit)
    wird der aktuelle Stand von `main` auf GitHub Pages veröffentlicht;
  - **sofort** per Knopf: Actions → „App veröffentlichen“ → „Run workflow“.
  - Ein Push auf `main` löst keine Veröffentlichung aus.
  - Nie zwei Veröffentlichungen gleichzeitig.
  - Im Protokoll des Laufs steht, welcher Commit und welche `APP_VERSION`
    veröffentlicht wurde.
- Die Minute 17 statt einer vollen Stunde ist gewählt, weil GitHub zu vollen
  Stunden stark ausgelastet ist und Läufe dann später starten.
- GitHub rechnet in UTC. Nach der Zeitumstellung am 25.10.2026 läuft es
  deshalb eine Stunde früher (2:17 Uhr). Das ist gewollt, beides ist nachts.
- `README.md`: Abschnitt „Veröffentlichen“ mit Knopf-Anleitung und Regel für
  Datenbank-Migrationen.

Hinweis: Bisher hat GitHub die Seite mit Jekyll gebaut. Jetzt werden die
Dateien unverändert ausgeliefert. Das Repo enthält keine Jekyll-spezifischen
Dateien, für die App ändert sich nichts.

## Manuelle Schritte (Reihenfolge)

1. Settings → Pages → Source = „GitHub Actions“ (bereits erledigt).
2. Dateien hochladen. Der Ordner `.github` beginnt mit einem Punkt und ist
   auf Mac/Windows oft ausgeblendet. Prüfen, dass im Repo danach
   `.github/workflows/veroeffentlichen.yml` existiert.
3. **Einmal von Hand veröffentlichen:** Actions → „App veröffentlichen“ →
   „Run workflow“. Seit der Umstellung in Schritt 1 veröffentlicht sonst
   niemand mehr, die Live-Seite bleibt bis dahin auf dem alten Stand.
4. Live-Seite neu laden, unten muss „Version 20.0.1“ stehen.

Keine Datenbank-Migration.

## Bekannte offene Punkte

- Der Workflow veröffentlicht jede Nacht, auch wenn sich nichts geändert hat.
  Das ist harmlos, die Seite bleibt gleich.
- GitHub schaltet geplante Läufe ab, wenn in einem öffentlichen Repo 60 Tage
  lang nichts gepusht wurde. Dann kommt eine Mail von GitHub; im Actions-Tab
  lässt sich der Workflow wieder einschalten.
- Datenbank-Migrationen laufen weiterhin von Hand (siehe README,
  „Veröffentlichen“).
