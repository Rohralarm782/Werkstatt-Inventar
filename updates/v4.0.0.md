# v4.0.0 — 30.09.2026

## Was wurde geändert und warum

**Kein Login mehr.** In 3.0.0 scheiterte die Anmeldung: Die App holte
den Datenbankschlüssel per Bearer-Token, Neon Auth erwartet dafür aber
das Sitzungs-Cookie. Statt das zu reparieren, entfällt die Anmeldung
ganz — die Daten sind nicht sensibel, der Link bleibt intern, und jede
Hürde senkt die Nutzung. Die App holt sich beim Öffnen einen anonymen
Schlüssel von Neon Auth (gilt eine Stunde, wird automatisch erneuert).

**Wer hat was gemacht.** Beim ersten Öffnen fragt jedes Gerät
„Wer bist du?“. Der gewählte Name wird auf dem Gerät gespeichert
(lokaler Browserspeicher, kein Cookie) und bei jeder Buchung und jedem
Ticket mitgeschrieben: Zugang, Ausgabe, Umbuchung, Inventur, Ticket
angelegt / übernommen / erledigt. Wechseln über den Namen oben rechts.
Das ist Vertrauenssache — jedes Gerät kann jeden Namen wählen.

**Löschschutz.** Ohne Anmeldung kann jeder mit dem Link die
Schnittstelle nutzen. Deshalb:
- Gelöscht werden können nur Renntermine und Packlisten-Zeilen.
  Buchungen, Tickets, Sportler, Artikel, Räder, Rechnungen nicht.
- Ins Buchungsjournal kommen von außen nur Zugänge. Entnahmen,
  Umbuchungen, Korrekturen und Rechnungsläufe gehen ausschließlich über
  die Datenbankfunktionen. Buchungen können nicht geändert werden.
- Statt löschen: Sportler, Artikel, Räder und Namen werden ausgeblendet
  (inaktiv), Tickets storniert.

## Manuelle Schritte

1. Neon SQL-Editor: Inhalt von `db/migration_4.0.0.sql` vollständig
   ausführen (Neons Beispieltext im Editor vorher entfernen). Vorhandene
   Daten bleiben erhalten. **Nicht** `schema.sql` — die ist nur für eine
   neue, leere Datenbank.
2. Data API → **Refresh schema cache**.
3. `index.html`, `VERSION.md`, `updates/v4.0.0.md`,
   `db/migration_4.0.0.sql` und `db/schema.sql` hochladen.
4. App öffnen, „Wer bist du?“ → eigenen Namen eintragen.
5. Optional: Das in 3.0.0 angelegte Konto unter Neon → Auth → Users
   löschen; es wird nicht mehr gebraucht.

## Geprüft

- Migration und Neuinstallation ergeben exakt dieselbe Datenbankstruktur
  (286 Merkmale inkl. Rechten und Zugriffsregeln).
- 30 Abläufe gegen PostgREST mit anonymem Schlüssel, darunter alle
  Löschversuche (abgelehnt) und direkte Journal-Manipulation (abgelehnt).
- Oberfläche: alle Ansichten und Aktionen im Browser-Simulator.

## Bekannte offene Punkte

- Neon Data API und Neon Auth sind bei Neon noch im Beta-Status.
- Fotos am Ticket, eigene Bestellliste: noch nicht umgesetzt.
- Safari auf dem iPhone löscht den lokalen Speicher von Websites, die
  sieben Tage nicht geöffnet wurden — dann fragt die App erneut nach dem
  Namen. Als App zum Home-Bildschirm hinzugefügt passiert das nicht.
