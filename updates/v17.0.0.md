# v17.0.0 — 06.10.2026

Grundlage: Repo-Stand `1ec352e` (16.0.0).

Reiner Umbau ohne neue Funktionen und ohne Änderung am Verhalten: Die
`index.html` (5480 Zeilen, rund 730 KB) ist in mehrere Dateien aufgeteilt.
Größerer Umbau der Struktur, daher 17.0.0. Keine Datenbankänderung.

## Was wurde geändert und warum

Bisher steckte alles in einer Datei: ZXing (336 KB in einer Zeile), das
gesamte CSS und rund 5000 Zeilen App-Code. Änderungen waren schwer
nachzuvollziehen, und jedes Update musste die komplette Datei liefern.

Neue Aufteilung:

- `index.html` — nur noch Gerüst (Kopf, Reiter, Bereiche), `APP_VERSION`
  und die Einbindung aller Dateien.
- `css/app.css` — das bisherige `<style>` unverändert.
- `lib/zxing.min.js` — die bisher eingebettete ZXing-Bibliothek
  unverändert (weiterhin kein CDN).
- `js/` — der App-Code, nach Bereichen geschnitten:
  `core.js`, `tickets.js`, `lager.js`, `etiketten.js`, `inventur.js`,
  `inventar.js`, `verwaltung.js`, `scanner.js`, `aktionen.js`,
  `konto.js`, `start.js` (Inhalt siehe README.md).

Der Code ist nur verschoben, nicht umgeschrieben. Jede Datei hat oben
einen kurzen Kopfkommentar; sonst sind alle Zeilen unverändert. Die
Dateien sind normale `<script>`-Dateien (keine Module, kein Build-Schritt)
und teilen sich wie bisher den globalen Bereich. Einzige inhaltliche
Verschiebung: `APP_VERSION` steht jetzt direkt in der `index.html`.

Neu: Jede eingebundene Datei trägt die Version im Pfad
(`js/lager.js?v=17.0.0`). So lädt der Browser nach einem Update alle
Dateien neu und mischt keine alten mit neuen. Bei jedem künftigen Update
müssen `APP_VERSION` und alle `?v=`-Angaben in der `index.html` angepasst
werden (die `index.html` ist dadurch immer Teil des Updates).

Reihenfolge der Einbindung ist wichtig: Code, der beim Laden sofort läuft
(z. B. `Object.assign(A, …)` in `konto.js`), darf nur auf Dinge aus
derselben oder einer früher geladenen Datei zugreifen. `start.js` kommt
immer zuletzt.
