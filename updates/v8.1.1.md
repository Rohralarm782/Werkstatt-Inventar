# v8.1.1 — 02.10.2026

Grundlage: Repo-Stand `5f5b600` (8.1.0).

Reine Fehlerbehebung, keine neuen Funktionen, keine Datenbankänderung.

## Was wurde geändert und warum

### Doppeltipp bucht doppelt (wichtigster Fix)
- **Problem:** Während gespeichert wurde, war nur die Seite gesperrt, nicht
  der Dialog darüber. Ein zweiter Tipp auf „Buchen“ (Zugang, Ausgabe,
  Inventur, Storno, Rechnung …) bei langsamem Netz hat die Buchung ein
  zweites Mal geschickt.
- **Jetzt:** Solange eine Änderung läuft, startet keine zweite. Der Dialog
  ist in der Zeit ausgegraut; ein weiterer Tipp zeigt „Moment — es wird
  noch gespeichert.“

### Rad-QR ohne Netz
- **Problem:** Am Wettkampf ohne Netz öffnete der QR-Code am Rad zwar die
  App mit dem gespeicherten Stand, aber nicht das neue Ticket.
- **Jetzt:** Auch offline öffnet sich direkt „Neues Ticket“ für das Rad;
  das Ticket wird wie gewohnt nachgesendet.

### Rechnung drucken nach Etikettendruck
- **Problem:** Nach dem Druck auf Etikettendrucker-Format (62 × 29 mm) blieb
  dieses Seitenformat aktiv. Eine danach gedruckte Rechnung kam im
  Etikettenformat.
- **Jetzt:** Nach dem Etikettendruck gilt wieder das normale Seitenformat.

### Scannen im Inventar
- Eine gescannte Einzelstück-Nummer wird auch angezeigt, wenn oben eine
  andere Kategorie gewählt war (der Kategorie-Filter wird dafür
  aufgehoben). Vorher stand dann „Nichts gefunden“.
- Ein Lager-Artikel-Code öffnet im Inventar direkt das Artikel-Menü.
- Unbekannte Nummern melden sich mit Fehlerton und Hinweis.
- Im Lager meldet ein gescannter Einzelstück-Code jetzt „ist ein
  Einzelstück — unter Inventar scannen“ statt „Unbekannter Code“.

### Kleinere Fehler
- **Ticket stornieren:** Schlug das Stornieren fehl, sprang die App
  trotzdem zurück zur Liste. Jetzt bleibt das Ticket offen.
- **Abgelehnte Offline-Tickets für Einzelstücke:** In der Liste fehlte
  der Name (nur „· Problem“). Jetzt steht die Teilenummer da.
- **Einzelstück an einem inaktiven Rad:** Die Ort-Auswahl zeigte
  fälschlich „Werkstatt“. Jetzt steht das Rad drin.
- **Termin löschen:** ging mit einem Tipp ohne Rückfrage. Jetzt mit
  Rückfrage.
- **Shop-Link:** Ohne `https://` eingetragen („www.rose.de/…“) war der
  Link kaputt. Er wird jetzt ergänzt; andere Link-Arten werden nicht
  geöffnet.
- **Reiter „Lager“:** Antippen aus der Bestellliste führt jetzt zurück
  zur Lager-Übersicht (eine laufende Inventur bleibt erhalten).
- **Namen eintragen:** Ein ausgeblendeter Name, erneut eingetragen,
  erzeugte einen Fehler und die App fragte bei jedem Start wieder. Jetzt
  wird der Name wieder eingeblendet und gewählt.

## Geprüft

Im Browser mit Testdaten:
- Doppeltipp auf „Buchen“ im Zugang-Dialog bei langsamem Netz → genau
  eine Buchung gesendet.
- Start ohne Netz über `?rad=BR-01` → neues Ticket für das Rad.
- Scan einer Nummer bei anderer Kategorie → Teil sichtbar; Artikelcode
  im Inventar → Artikel-Menü.
- Shop-Link `www.rose.de/kette` → `https://www.rose.de/kette`.
- Einzelstück an inaktivem Rad → Rad in der Ort-Auswahl.
- Keine JavaScript-Fehler.

## Bekannte offene Punkte

- **Bestellliste und Koffer-Tickets:** Fehlt Material für ein Ticket,
  das im Koffer bearbeitet wird, erscheint es zwar als Grund, erzeugt
  aber keinen eigenen Bedarf in der Bestellliste.
- **Zwei Arten „nachbestellen“:** Der Filter „Nachbestellen“ im Lager
  (nur Mindestbestand) und die Bestellliste (plus Koffer, Tickets, offene
  Bestellungen) rechnen verschieden. Wird mit der neuen Menüstruktur
  zusammengeführt.
